{% comment %} Per-window request-usage progress bars (daisyUI linear ``progress``). Context vars: - usage: per-token dict from gateway.rate_limiting.get_per_token_usage(token_ids)[token_id], keyed by window name ("min"/"hour"/"day"), each {"req": float, "in": int, "out": int}. - limits: a management.models.LimitSet whose windows() yields (name, secs, rpm, itpm, otpm) tuples (finest-first: min, hour, day). Two bars are shown side by side — per hour and per day — each ~half width. The hour/day caps are derived from the per-minute cap via the resolved multipliers (``rpm * multiplier``), so they are usually much larger and only fill materially with sustained traffic. Windows with no request limit (None) render no bar — only the "—" count text — since there is no cap to measure against. When a limit is set, the bar fill is clamped to 100%; the count text shows the real ``used/limit`` counts (which may exceed the cap when over limit). Colors shift to warning at >=80% and error at >=100%. {% endcomment %} {% load i18n ui %}
